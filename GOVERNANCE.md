# Governance

This document describes how the InferenceExchange organization makes
decisions. It applies to all repositories in the organization.

## Principles

- **Open.** Design, discussion, and decisions happen in public, in
  issues, pull requests, and discussions.
- **Vendor neutral.** Decisions are made on technical merit. No
  company, product, or implementation has privileged status.
- **Specification first.** The specification and its conformance
  suite define the protocol. Reference implementations exist to prove
  the specification, not to lead it.

## Roles

- **Contributors** — anyone who participates: issues, pull requests,
  reviews, discussions. No membership is required.
- **Maintainers** — contributors with merge rights, listed in
  [MAINTAINERS.md](MAINTAINERS.md). Maintainers review and
  merge changes and are responsible for the health of their
  repository.

Maintainers are added by nomination and consensus of the existing
maintainers, based on a record of sustained, quality contribution.
Maintainers who are inactive for an extended period may be moved to
emeritus status.

## Decision making

- Day-to-day changes are decided by **lazy consensus** on the pull
  request or issue: no objections from maintainers within a
  reasonable review period means acceptance.
- Substantial changes — protocol changes, new repositories, changes
  to this document — start as a public proposal and require consensus
  among maintainers. If consensus cannot be reached, a simple
  majority vote of maintainers decides.

## Communication

All communication happens on GitHub — issues, pull requests, and
[discussions](https://github.com/orgs/InferenceExchange/discussions).
There are no private decision-making channels.
